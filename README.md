**Video Stats Bot** — Telegram-бот для удобного отслеживания статистики просмотров видео с YouTube и ВКонтакте в одном месте.

> Разработан в рамках хакатона МИФИ 2026  
> **Заказчик:** Дмитрий Боровков

## 💡 Как это работает?

Добавьте ссылки на ваши видео — и бот автоматически соберёт и сохранит всю статистику.

- отправьте ссылку через кнопку `Добавить ссылку`;
- бот определит платформу (YouTube или ВКонтакте);
- получит актуальные просмотры и сохранит их в базе;
- будет отслеживать изменения со временем;
- покажет список всех видео и суммарную статистику.

В результате вы видите не только общий охват, но и динамику просмотров ваших видео — в одном месте, без ручной проверки каждой платформы.

```
👤 Пользователь
│
│ /add https://youtu.be/...
▼
🤖 Telegram Bot
│
│ Определяет платформу (YouTube / VK)
▼
🔍 API платформы
│
│ Возвращает необходимые данные
▼
🗄️ PostgreSQL
│
│ Сохраняет и считает
▼
📊 Статистика
│
│ Список видео + сумма просмотров
▼
👤 Пользователь
```

> **Целевая аудитория:** Владельцы контента, блогеры, SMM-специалисты и digital-агентства, которым нужно в одном месте отслеживать динамику и статистику просмотров без ручного захода на каждую платформу.

## 🚀 Возможности

- **Приём ссылок на видео** через Telegram-бота;
- **Автоматическое определение платформы** (YouTube \ VK Video);
- **Получение и сохранение** актуального количества просмотров через официальные API;
- **Вывод списка** всех добавленных видео с текущей статистикой;
- **Агрегация данных**: общее количество видео и суммарные просмотры;
- **Обновление статистики** по требованию (инлайн-кнопка);
- **Обработка ошибок** при недоступности платформ (сохранение последних данных + понятный статус);
- **Полная контейнеризация** (Docker Compose) для простоты развертывания.

## 📋 Требования для развертывания

Для запуска **собственного экземпляра** бота вам понадобится:

### Сервер
- Linux (Ubuntu 20.04+ рекомендуется);
- RAM - 1 Гб / SSD 20 Гб;
- Docker Engine 20.10+;
- Docker Compose 1.29+;
- Доступ к Telegram API, YouTube API и VK API.

### Учётные записи и ключи
- **Telegram Bot Token** — получить у [@BotFather](https://t.me/BotFather);
- **Telegram ID пользователя** - посмотреть у себя в телеграм-аккаунте (доступ будет только у пользователей вписаных в `.env`)
- **YouTube Data API Key** — получить в [Google Cloud Console](https://console.cloud.google.com/apis/credentials), квота составляет `10 000` запросов в сутки;
- **VK Data API Key** - получить в [VK для разработчиков](https://dev.vk.com/ru/api/access-token/service-token);
- **PostgreSQL** (опционально, если не используете Docker-образ) — база данных.

#### Как получить Telegram Bot Token
- Перейдите в [@BotFather](https://t.me/BotFather);
- Теперь нужно ввести команду `/newbot` и отвечать на сообщения BotFather. Он предложит ввести `name` и `username` бота, а затем выдаст токен, который нужно сохранить.

#### Как узнать Telegram ID пользователя
- Откройте настройки Telegram;
- Перейдите в "Продвинутые настройки";
- Перейдите в "Экспериментальные настройки";
- Включите "Show Peer IDs in Profile";
- Теперь, если открыть профиль любого пользователя, вы сможете увидеть его ID.

#### Как получить YouTube Api Key
- Перейдите на [Google Cloud Console](https://console.cloud.google.com/apis/credentials);
- Войдите в свой аккаунт;
- Создайте проект;
- Затем в `API Library` найдите `YouTube Data API v3` и включите его для своего проекта;
- Вернитесь на главную страницу и во вкладке `Credentials` Нажмите `+ Create credentials` -> `API key`;
- Создайте API ключ; 
- Сохраните его для дальнейшего использования.

#### Как получить VK API Key
**1 Вариант:**
- Перейдите в [VK для разработчиков](https://dev.vk.com/ru);
- Войдите в свой аккаунт;
- Перейдите в [список приложений](https://dev.vk.com/ru/admin/apps-list);
- Создайте мини-приложение: "Создать приложение" → "Тип приложения" → "Мини-приложение";
- Дайте ему название и напишите любое описание, сохраните изменения;
- Администратор мини-приложения получит сервисный ключ в панели управления в разделе Разработка → Ключи доступа
- Сохраните сервисный ключ для дальнейшего использования.

**2 Вариант:**
- Перейдите в [VK для разработчиков](https://id.vk.com/business/go);
- Войдите в свой аккаунт;
- Нажмите "Приложения" → "Создать приложение";
- Выберите тип приложения "Standalone-приложение";
- Заполните имя и другие поля, подтвердите аккаунт через гос услуги  → "Создать приложение";
- После создания вы получите ID приложения;
- Открыть ссылку `https://oauth.vk.com/authorize?client_id=CLIENT_ID&display=page&scope=video&response_type=token&v=5.131` в браузере, заменив CLIENT_ID на ID своего приложения;
- Разрешить приложению доступ к аккаунту;
- В адресной строке будет: `https://oauth.vk.com/blank.html#access_token=ТОКЕН&expires_in=86400&user_id=123456`, `access_token=ТОКЕН` — это и есть ключ.

## 🚀 Быстрый старт (Self-Hosted)

Следуйте этой инструкции, чтобы развернуть сервис на вашем сервере:

### Шаг 1: Клонировать репозиторий
```bash
git clone https://github.com/3axap4yk/video-stats-bot.git
cd video-stats-bot
```

### Шаг 2: Настроить переменные окружения
Создайте файл `.env` из шаблона и заполните его реальными значениями:
```bash
cp .env.example .env
nano .env
```
Подробное описание всех переменных — в разделе [«Конфигурация (.env)»](#️-конфигурация-env).

### Шаг 3: Запустить сервис
```bash
./run
```
Скрипт `run` автоматически:
- проверяет доступ к Telegram-API;
- проверяет установку необходимых программ;
- собирает проект через Gradle;
- удаляет старые контейнеры (если они уже существуют);
- пересобирает Docker-образы;
- поднимает PostgreSQL и backend через docker-compose;
- выводит логи бота.

### Краткая проверка работоспособности:

1. Проверьте запуск контейнеров:
```bash
docker ps
```
Вы должны увидеть контейнеры `video_stats_bot` и `video_stats_db` в статусе `Up`.

2. Проверьте логи:
```bash
docker-compose logs -f
```
3. Найдите вашего бота в Telegram по имени и отправьте команду `/start`.

### Скрипты и их использование

Помимо скрипта запуска `./run`, описанного выше, имеются также:

### 🔄 Обновление проекта

```bash
./update
```
Скрипт update автоматически:
- проверяет доступность YouTube API;
- проверяет доступность VK API;
- создаёт резервную копию PostgreSQL перед обновлением;
- сохраняет SQL-бэкап в папку backups/;
- обновляет проект через git pull;
- останавливает старые контейнеры;
- пересобирает backend через Gradle;
- пересобирает Docker-образы;
- запускает PostgreSQL и backend заново;
- проверяет готовность базы данных;
- выводит последние логи бота после запуска.

> Рекомендуемый способ обновления проекта.
### 📦 Создание резервной копии БД

```bash
./scripts/create-backup.sh
```
Скрипт create-backup.sh автоматически:
- подключается к контейнеру PostgreSQL;
- создаёт SQL-дамп базы данных через pg_dump;
- сохраняет резервную копию в папку backups/;
- проверяет целостность бэкапа;
- показывает размер файла;
- выводит список последних резервных копий.

Пример результата
```
backups/backup_2026-05-07_14-30-22.sql
```
> Рекомендуется выполнять перед обновлениями, миграциями и экспериментами с БД.

### 🚚 Экспорт БД для миграции на другой сервер

```bash
./scripts/export-for-migration.sh
```
Скрипт export-for-migration.sh автоматически:
- создаёт полный SQL-дамп PostgreSQL;
- сохраняет его в папку backups/;
- проверяет корректность дампа;
- генерирует готовую инструкцию по переносу базы данных;
- показывает команды scp для копирования дампа на новый сервер.

Когда использовать?

- перенос проекта на новый VPS;
- миграция между серверами;
- создание off-site backup;
- перенос production-данных.

### ♻️ Восстановление базы данных из бэкапа

```bash
./scripts/restore-db.sh backups/your_backup_file
```
Скрипт restore-db.sh автоматически:
- проверяет наличие .env;
- проверяет существование файла бэкапа;
- запрашивает подтверждение перед восстановлением;
- полностью очищает текущую PostgreSQL-схему;
- восстанавливает базу данных из SQL-дампа;
- проверяет завершение операции.

> ⚠️ Внимание: восстановление полностью перезаписывает текущую базу данных.

Когда использовать?

- восстановление после сбоя;
- перенос данных;
- откат после неудачного обновления;
- восстановление тестового окружения.

## ⚙️ Конфигурация (.env)

Все настройки проекта находятся в файле `.env`. Ниже перечислены все переменные, которые необходимо заполнить:

### Telegram Bot
```
TELEGRAM_BOT_TOKEN=your_bot_token_here
```
### Whitelist
```
# Если несколько ID, то записывайте через запятую без пробелов
TELEGRAM_WHITELIST_IDS=your_telegram_id_here1,your_telegram_id_here2
```
> Внимание: Если вы оставите `TELEGRAM_WHITELIST_IDS` пустым, то доступ к боту будет у всех пользователей!

### YouTube API
```
YOUTUBE_API_KEY=your_youtube_api_key_here
```

### VK API
```
VK_ACCESS_TOKEN=your_vk_access_token_here
VK_API_VERSION=5.131
```

### База данных
```
DB_HOST=db
DB_PORT=5432
DB_NAME=your_db_name_here
DB_USER=your_username_here
DB_PASSWORD=your_password_here
```
> Внимание: Файл `.env` содержит секретные данные. Никогда не добавляйте его в репозиторий — он уже находится в .gitignore.

## 🔐 Управление транзакциями

Проект обеспечивает целостность данных на всех уровнях:

- **Одиночное сохранение** — видео и платформенные ID сохраняются в одной транзакции (videos + youtube/vk)
- **Batch-обновление** — массовое обновление статистики выполняется в единой транзакции с полным откатом при ошибке
- **Идемпотентность** — `ON CONFLICT` гарантирует отсутствие дублей

При любой ошибке выполняется `rollback()` — в БД не остаётся "половинчатых" данных.

### Ошибки при запуске

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `port is already allocated` | Порт 5432 уже занят другим PostgreSQL или программой | `docker stop $(docker ps -q --filter "publish=5432") && docker rm $(docker ps -aq --filter "publish=5432")`, затем перезапустить |
| `409 Conflict: terminated by other getUpdates request` | Запущено два экземпляра бота с одним токеном Telegram | Удалите старые контейнеры: `docker ps -a \| grep video_stats` и `docker rm <лишние_ID>` |
| `UnknownHostException: api.telegram.org` | Контейнер не может разрешить DNS-имена | Проверьте интернет на сервере: `ping api.telegram.org`. Если интернет есть — перезапустите Docker: `sudo systemctl restart docker` |
| `FATAL: database does not exist` | База данных не создалась при первом запуске | Выполните: `docker compose down -v && docker compose up -d`. Это пересоздаст том с базой |
| Контейнер падает сразу после старта | Ошибка в переменных окружения | Проверьте логи: `docker compose logs --tail=50`. Скорее всего, неверный токен или ключ API |

---

### Проблемы с Telegram ботом

| Симптом                                       | Причина | Решение |
|-----------------------------------------------|---------|---------|
| Бот не отвечает на команды                    | Контейнер упал или не запустился | Проверьте: `docker ps \| grep video_stats_bot`. Если нет — `docker compose up -d` |
| `401 Unauthorized` в логах                    | Неверный токен бота | Проверьте `TELEGRAM_BOT_TOKEN` в `.env` — скопируйте его заново от @BotFather. Убедитесь, что в токене нет лишних пробелов |
| Бот отвечает, но не добавляет видео           | Неверный или неактивный YouTube API ключ | Проверьте `YOUTUBE_API_KEY` в `.env`. Убедитесь, что YouTube Data API v3 **включён** в Google Cloud Console |
| Бот работал и перестал обновлять статистику, `403 quotaExceeded` в логах | Исчерпана дневная квота YouTube API (10 000 запросов) | Дождитесь сброса квоты (следующие сутки по тихоокеанскому времени) или создайте новый API ключ в другом проекте Google Cloud |

---

### Проблемы с базой данных

| Симптом | Причина | Решение |
|---------|---------|---------|
| Данные теряются после перезапуска | Том PostgreSQL не настроен или был удалён | Обычно данные сохраняются. Если пропали — проверьте: `docker volume ls \| grep postgres_data`. Если тома нет — он был удалён вручную |
| `Ошибка инициализации пула соединений` в логах | База данных недоступна или неверные параметры | Проверьте, что контейнер `video_stats_db` в статусе `Up`: `docker ps` |
| Бот запущен, но список видео пустой | База данных была пересоздана | Данные хранятся в томе Docker. Если вы выполняли `docker compose down -v`, данные удалены безвозвратно |

### Проблемы с Docker

| Симптом | Причина | Решение |
|---------|---------|---------|
| `docker: command not found` | Docker не установлен | Установите: `sudo apt update && sudo apt install docker.io docker-compose -y` |
| `permission denied` при запуске | Ваш пользователь не в группе `docker` | `sudo usermod -aG docker $USER`, затем **переподключитесь к серверу** (выйдите и зайдите заново) |
| Контейнеры не запускаются после перезагрузки сервера | Не настроен автозапуск Docker | Включите автозапуск Docker: `sudo systemctl enable docker`. |
| Образ не обновляется после `git pull` | Docker использует закэшированные слои | Запустите с флагом: `docker compose up -d --build --force-recreate` |
| `no such service` при просмотре логов | Неверное имя сервиса | Используйте `docker compose logs backend`, а не `docker compose logs video_stats_bot` |

### Общие рекомендации при проблемах

1. **Смотрите логи:**
```
docker compose logs backend --tail=100
docker compose logs db --tail=50
```
2. **Проверяйте статус контейнеров:**
```
docker ps -a
```
3. **Перезапустите с чистого листа (осторожно — удалит все данные БД!):**
```
# Предварительно выполните: ./scripts/create-backup
docker compose down -v
docker compose up -d --build --force-recreate
```
4. **Проверьте доступность внешних API:**
```
curl -I https://api.telegram.org
curl -I https://www.googleapis.com
curl -I https://api.vk.com
```
